1. Choose a task and describe the wanted result, keeping unknowns visible instead of inventing values.
2. Find Knowledge map, read relevant guidance and return without losing the project.
3. Review an applicable practice, explain its proposed changes, cancel once and then apply deliberately. Reverse the change with Undo.

5. Explain the output recommendation, choose the smallest useful output and identify what its download includes and omits.
6. Use the matched handoff or host guide. Distinguish expected behavior, format checks and actual observations.
7. Download the selected output, reopen it and find the same decisions. Understand that complete generation remains available from the configuration.
8. Give its readable HTML to a colleague and check whether they can understand the outcome, next owner and unresolved decisions.

## Audit outcome, 3 October 2026

The current build is a useful candidate for a focused beta. Its supported authoring and portable-file journeys work in the exercised cases. A claim of universal workflow coverage, successful Copilot behavior or worldwide product leadership is not established.

The audit corrected concrete defects:

1. A process study can remove its final repository component instead of inventing a code location.
2. Project-level checks can stay unassigned and reopen through supported metadata formats. Blank observations stay blank.
3. Imported candidate choices survive editing and navigation. Rejected facts do not become accepted during a panel redraw.
4. Removing a fact or check restores keyboard position to a remaining record or its Add control.
5. Changed skill resources with the same filename show their skill context and exact path.
6. Download and detailed review put errors before advisory notes. Packaging failures remain visible.
7. Project JSON import and export share a bounded serializer. Oversized input is rejected without truncation.
8. Maven candidates exclude commented and nested profile declarations. Effective configuration is still unresolved.
9. Case-renamed and Unicode-equivalent filenames can be compared across generations. Duplicate destinations within a file set still reject.
10. Component and archive paths agree about Windows reserved device names.
11. Removing all components no longer bypasses required agent-run test or build commands. Componentless studies and supplied-context reviews remain supported.
12. Source filters distinguish repository hosts from GitHub documentation and gists, identify the Google research paper and classify the Agent Skills specification as a standard.

Generated Ponytail and Spec Kit guidance now points to inspected revisions. The primary LLM Wiki gist is linked directly, with the live review date and conceptual limits. The original 105 topics and 55 sources remain, with 56 current source records.

The local browser exercise verified rejected and selected import candidates across panel changes, componentless study authoring, project checks, keyboard position after removal, distinct artifact labels and error-first Download review. An actual downloaded ZIP and JSON were inspected on disk. Reopening the ZIP restored the same decisions, zero components and a project check with no invented observation. At 320 CSS px, the inspected evidence panel had no horizontal document overflow, a named modal, inert background, focus wrapping and Escape return. Both themes were inspected. The 96 compiler, archive, importer, comparison and portable checks passed.
